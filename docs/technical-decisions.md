# llm-finetune-platform 技术决策记录

**创建时间：** 2025-10-23  
**维护人：** 架构组（初始记录：zephyr）

---

## 架构与平台基线

- **总体架构**：一期采用单体服务（FastAPI）+ 明确模块边界的方式，聚合数据、训练、评估、部署、治理模块；后续按业务成熟度拆分微服务。  
- **部署形态**：容器化部署（Docker），使用 Docker Compose 管理前后端、任务队列、数据库与 vLLM，可在单机 GPU 环境中一键启动；后续规模扩大再评估 Kubernetes。  
- **工作空间隔离**：逻辑多租户（数据库 schema + 对象存储前缀隔离），结合权限模型确保团队隔离。

## 数据与存储

- **数据处理框架**：Pandas/Polars + 自研规则引擎，覆盖清洗、脱敏、质量评估，暂不引入 Spark。  
- **存储方案**：本地文件系统按约定目录存放原始/清洗/增强数据与模型文件（预留迁移至 S3/OSS），PostgreSQL 管理项目、训练、评估等元数据；向量库（FAISS/Milvus）按需启用；审计日志可先写入数据库或本地日志，后续再引入集中式日志系统。  
- **加密策略**：静态数据通过文件系统权限与可选 AES 加密保护，未来对接云存储时启用 KMS；传输层统一走 HTTPS/TLS。

## 模型训练与推理

- **训练框架**：PyTorch + HuggingFace Transformers + PEFT（后续如需 RLHF，再评估引入 TRL）；任务调度使用 Celery + Redis。  
- **参数高效策略**：首期支持 LoRA、QLoRA、DoRA，默认提供 QLoRA + DoRA 模板。  
- **GPU 资源管理**：使用自有 GPU 服务器（RTX 4090/5090、GB200 等），统一队列调度并记录资源使用。  
- **推理栈**：vLLM 为主推理引擎，预留与 Triton/KServe 的集成能力。

## 应用与前端

- **后端框架**：Python/FastAPI，暴露 REST API；内部事件使用 Redis Stream 触发训练、评估、部署。  
- **前端技术**：React + Tailwind CSS，支持多语言与暗/亮主题。  
- **身份认证**：一期采用平台账号体系并支持 MFA，SSO（SAML/OIDC）作为后续增强。

## 可观察性与运维

- **监控体系**：MVP 阶段使用 Python logging 输出训练/评估日志，并通过平台内 “Training Log” 面板实时展示；必要时补充轻量 `/health` `/metrics` 接口；Prometheus/Grafana 作为后续增强选项。  
- **告警联动**：初期通过应用内通知/邮件提示任务失败；后续根据需要再接入 Alertmanager 或 IM 通道。  
- **发布策略**：CI/CD 生成 Docker 镜像并推送 registry，目标环境拉取后执行 `docker compose up`; 成熟后再考虑 GitOps。

## 安全与合规

- **脱敏规则**：自研规则引擎 + 开源检测库（Presidio 等），支持客户自定义策略。  
- **审计日志**：关键操作写入不可变日志并定期归档/备份。  
- **权限模型**：以 RBAC 为主，结合属性条件（ABAC）逐步加强。

## 待定 / 风险跟踪

- GPU 采购与租赁策略需与基础设施团队确认。  
- 行业客户（金融/医疗）合规与审计要求需进一步细化。  
- 需评估自动评估脚本与人工标注伙伴的合作模式。
