# llm-finetune-platform Product Requirements Document (PRD)

**Author:** zephyr  
**Date:** 2025-10-23  
**Project Level:** 3  
**Target Scale:** 企业级多租户 SaaS 平台（Level 3 复杂系统）

---

## Goals and Background Context

### Goals

- 打造一套可复用的“大语言模型微调一站式平台”，覆盖数据→训练→部署→评估→治理全链路。  
- 帮助缺乏深度模型经验的企业客户在 2 周内完成首个微调闭环。  
- 建立标准化交付能力，支撑至少 2 个 PoC 客户并沉淀 10+ 可复用模板。  
- 为后续商业化合作打基础，实现“边实践边沉淀”的内部能力成长。

### Background Context

- 市场对微调能力需求旺盛，但企业自建成本高、风险大、缺乏经验。  
- 现有工具链（LoRA/QLoRA/DoRA、LlamaFactory）偏专业，无法满足端到端交付。  
- 灾难性遗忘、指标恶化、数据安全与合规是客户最担心的问题。  
- 我们需要一个平台化方案，一边学习积累方法论，一边对外提供标准服务。

## Requirements

### Functional Requirements

1. **数据与语料工作台**  
   - 支持多源数据导入（上传/API/对象存储指针），并记录来源元数据。  
   - 提供数据清洗（去重、噪声、敏感词/PII 脱敏）与质量评估仪表盘。  
   - 一键格式标准化为 JSONL/SFT/Parquet，支持版本管理与差异对比。  
   - 提供常用数据增强策略（语义改写、翻译、合成 QA）及可配置规则。  

2. **微调执行引擎**  
   - 内置 LoRA/QLoRA/DoRA 模板，支持默认超参与高级自定义。  
   - 向导式训练编排：选择模型→数据集→参数→资源→启动。  
   - 实时监控 loss、困惑度、显存、吞吐；提供告警阈值与通知。  
   - 自动生成训练快照，支持断点续训与一键回滚。  
   - 保存完整元数据：模型版本、数据版本、参数、日志。  

3. **部署与服务平台（vLLM）**  
   - 支持部署基座与微调后模型，多版本管理、灰度发布、回滚。  
   - 提供 API/SDK、鉴权、限流、调用统计、日志审计。  
   - 性能监控（QPS、延迟、Token 使用、资源占用）与告警。  

4. **评估与监控中心**  
   - 训练前后自动执行标准测试集，对比关键指标并生成可视化报告。  
   - 支持行业模板（客服、金融等）、自定义测试集与人工标注反馈入口。  
   - 记录评估历史，与训练任务关联，可下载 PDF/Markdown 报告。  

5. **治理与协作**  
   - 流程看板展示数据→训练→评估→部署进度与责任人。  
   - 工作空间级权限管理、操作日志、审批流，支持多团队协作。  
   - 集成通知（邮件/Slack/企业微信）与任务指派。  

### Non-Functional Requirements

- **安全性**：数据传输与存储全程加密，提供脱敏策略、操作审计、最小权限访问。  
- **可靠性**：训练任务失败具备自动重试与手动恢复流程，服务 SLA ≥ 99.5%。  
- **可扩展性**：支持按需扩展 GPU 集群，推理服务可水平扩容。  
- **可观察性**：统一日志、指标、链路追踪，支持问题回溯。  
- **可用性**：提供向导式界面、默认参数、操作提示，新用户在 1 天内完成培训。  
- **性能**：标准 7B 模型微调在 2×A100/80G 下 12 小时内完成；推理延迟（P95）< 800ms。

## User Journeys

1. **企业数据科学家导入数据并发起微调**  
   - 登录平台 → 创建项目 → 上传行业语料 → 执行清洗/脱敏 → 查看质量评分 → 选择模板 → 配置训练 → 监控任务 → 下载评估报告 → 提交上线申请。  
2. **内部交付团队构建示范项目**  
   - 使用现有模板复制项目 → 导入示例数据 → 复用最佳实践配置 → 生成评估报告 → 输出案例材料给销售团队。  
3. **合作伙伴部署并运营微调模型**  
   - 接收模型包 → 在 vLLM 托管环境一键部署 → 配置 API 密钥与限流 → 查看调用监控 → 持续关注质量告警与回滚建议。

## UX Design Principles

- **引导式**：用分步流程和默认参数帮助新手完成操作。  
- **透明可视**：训练、评估、部署进度和指标一目了然。  
- **安全可信**：敏感操作需二次确认并提供可追踪记录。  
- **合作友好**：多人协作状态、任务分配清晰，支持评论与批注。

---

## User Interface Design Goals

- 仪表盘展示关键指标（训练状态、评估结果、部署流量）。  
- 重要操作（数据上传、训练启动、发布）提供向导与状态条。  
- 重视报告可读性，图表与文本结合，支持导出/分享。  
- 提供暗色/亮色模式和多语言能力，方便不同团队使用。

## Technical Considerations

### Platform Requirements

- Web 管理控制台 + API 接口，首期提供平台账号体系；SSO 作为后续增强能力。  
- 内置 GPU 训练/推理服务器（首批配置 RTX 4090/5090、GB200 等），统一调度与监控。  
- 数据与模型文件存放在对象存储，向量检索需求使用轻量向量库（FAISS/Milvus），满足高并发读写。  
- 日志与审计通过后端日志流 + 平台内“Training Log” 面板呈现，支持实时查看；后续再评估引入 Prometheus/Grafana。  
- 预留离线备份与灾备机制，确保模型与数据可恢复。

### Technology Preferences

- 训练栈：PyTorch + HuggingFace Transformers + PEFT（后续若做 RLHF，再引入 TRL）。  
- 任务编排：Celery + Redis 队列，支持断点续训与任务追踪。  
- 平台后端：Python/FastAPI，提供 RESTful API 与后台作业管理。  
- 前端：React + Tailwind CSS，兼顾开发效率与可定制化 UI。  
- 数据处理：Pandas/Polars + 内置规则引擎，满足清洗、脱敏、质量评估需求。  
- 推理：vLLM 作为主推理引擎，预留 Triton/KServe 接口以便后续多引擎扩展。

### Architecture Considerations

- 一期采用“单体服务 + 明确模块边界”架构，进程内划分数据、训练、评估、部署、治理模块。  
- 通过内部事件总线（Redis/Kafka）串联异步任务，确保训练/评估/部署解耦。  
- 数据安全：全程 HTTPS、静态加密、最小权限访问，多工作空间隔离。  
- 扩展计划：为未来的模块拆分、外部系统集成（模型仓库、CI/CD）预留插件与 API。  
- DevOps：采用 Docker/Docker Compose 管理环境与部署，逐步演进到 GitOps 流程；待规模扩大再考虑 Kubernetes。
